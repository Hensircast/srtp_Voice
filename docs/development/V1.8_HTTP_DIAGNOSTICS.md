# V1.8 流式 HTTP 资源回收、连接复用与安全服务计时

本文说明 2026-09-30 批次已实现的流式 HTTP 行为，以及可复现的本地验证方法。只描述已落库代码与实际证据；未跑真实设备/服务的部分明确标注为待复测，不把规划写成完成。

## 1. 资源回收（生命周期）

`_request_ollama_text_stream` 在 payload 之后先把 `response` 置为 `None`，再用**最外层 try/finally** 覆盖：取得 response、`raise_for_status()`、读取 NDJSON、`done`/非空校验。最外层 `finally` 关闭**已取得**的 response；`post()` 自身抛错时仍为 `None`，不会伪造资源。读取迭代器的 `finally` 只关 reader，且读取失败也必须继续关闭 response。

所有可选 close 走 `_close_quietly()`：只吞普通清理异常，不覆盖原始取消/读取/提交故障，也不吞 `KeyboardInterrupt`/`SystemExit`。`emit(parts)`、`_validated_stream_reply(tokens)` 与 runtime 消费循环同样绑定迭代器并显式关闭，正常结束、取消、句子提交错误都恰好释放一次；不依赖 GC 或析构。

## 2. 连接复用（默认开启，显式启用）

* 开关：`STREAM_LLM_REUSE_HTTP`，`AppConfig.stream_llm_reuse_http` 默认 `True`（严格 `env_bool`，非法值报错）。
* 仅 `main.py` 的**流式 + Ollama** 路径调用 `enable_http_reuse()`；`0` 时保持借用 `requests` 模块逐次请求的旧行为。直接 `StrategyGenerator(cfg)`**不会**自动创建 Session。
* Session 惰性创建、进程私有、无全局/代理配置改动；一次只允许一个流持有租约。已有流占用时，新流回退为**独立模块请求**，而不是共享非线程安全的 Session 或等待整句结束。
* `close()` 幂等：空闲立即关闭；**忙时延迟关闭**，租约归还时在锁外关闭一次，不会 invalidate 正在读取的流。关闭后新的流请求在 fallback 之外明确抛错，不重开 Session。
* 包装失败会先关闭刚创建的 Session 再抛出，不泄漏；Session 构造失败不再静默降级为模块请求，交由既有 `llm_fallback_to_mock` 策略处理。

真实本地 HTTP/1.1 连接计数（无模型，Codex 独立复现）：两轮测试，每轮 `tags`+`chat` 共两个请求。四个请求在关闭复用时建立4条TCP连接；开启后 Content-Length 响应1条、chunked 响应2条、gated EOF响应2条，且 `done=true` 即停、不等 EOF。**这是连接层计数，不是 Ollama/模型/设备速度提升证据。**

## 3. 安全服务计时（诊断）

Ollama 在 `done=true` 的最终对象里上报整数纳秒与计数（官方依据：[api/usage](https://docs.ollama.com/api/usage)、[api/chat](https://docs.ollama.com/api/chat)）。本项目只做白名单提取：

| 服务端字段 | 导出名 | 处理 |
| --- | --- | --- |
| `total_duration` | `server_total_ms` | ns → ms，round 3 |
| `load_duration` | `model_load_ms` | ns → ms，round 3 |
| `prompt_eval_duration` | `input_processing_ms` | ns → ms，round 3 |
| `eval_duration` | `generation_ms` | ns → ms，round 3 |
| `prompt_eval_count` | `input_tokens` | 整数 |
| `prompt_eval_cached_count` | `input_cached_tokens` | 整数 |
| `eval_count` | `output_tokens` | 整数 |

* 原始服务字段只接受非 `bool` 的真实整数，范围 `0..2**63-1`。清洗已换算的 duration 时允许有限非负 `int`/`float`、上界 `(2**63-1)/1e6`（先范围检查再 `isfinite`），count 仍要求上述整数范围；零是合法值并保留。缺失/非法/过大一律丢弃，**不造 0**。
* 只有真正 `done` 且非 `done_reason=length` 的成功流才记录；取消、空流、截断、失败都不发布。同一 turn 内多个成功请求（例如 echo 修复）**分别**保留为独立条目，不合并、不平均，也不把失败请求冒充成功。
* 载体：`TextChunk.diagnostics`（原字段位置不变）→ runtime只在final token收集首个有效清洗结果，**最终待播文本先入队**，再emit **一次** `llm_diagnostics`；emit的是清洗副本（未知/私密字段不进入诊断事件）→ `TurnTimingSnapshot.backend_diagnostics`（可选字段，深清洗副本）。原日志仍含其他事件文字，不可对外发送整个事件文件。
* `backend_diagnostics` **不混入** `latencies_ms` 与 `summary`；摘要与 baseline 导出共用同一 sanitizer，导出**不含** model、URL、prompt、thinking、message、回复文本。
* 不新增 LLM 请求，不等待最终统计才开口：首 token/分句/播放时序口径不变。第一条观测不自动称为冷启动。

## 4. 安全 PowerShell 复测（与连续复测兼容）

只读脱敏产物，绝不外发录音、memory 或事件文字。每次运行使用新的 GUID 目录，保留本机实际模型地址，A/B 只改一个开关。

```powershell
Set-Location 'D:\code\VScode\Py\srtp_Voice'
$runName = 'http-diag-' + [Guid]::NewGuid().ToString('N')
$env:OUTPUT_DIR = "outputs/$runName"
$env:MEMORY_FILE = "$env:OUTPUT_DIR/memory.json"
$env:STATE_FILE  = "$env:OUTPUT_DIR/emotion_state.json"
# 本轮：复用开启；对照组复制同样命令，只把这一行改成 '0' 并另建 GUID 目录
$env:STREAM_LLM_REUSE_HTTP = '1'
.\venv\Scripts\python.exe -m tools.workbench doctor --online
.\venv\Scripts\python.exe -m tools.workbench snapshot --output "$env:OUTPUT_DIR/recording-context.json" --label $runName
.\venv\Scripts\python.exe main.py --mode vad --streaming --continuous
# 完成 6–10 轮后 Ctrl+C，仍在该终端保存同轮证据
.\venv\Scripts\python.exe -m tools.workbench baseline --metrics "$env:OUTPUT_DIR/streaming_metrics.json" --recording-metadata "$env:OUTPUT_DIR/recording-context.json" --output "$env:OUTPUT_DIR/timing-baseline.json" --measurement real --label $runName
$m = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_metrics.json" | ConvertFrom-Json
$m.turns | ForEach-Object {
    $reqs = $_.backend_diagnostics.llm_server_requests
    if (-not $reqs) { "turn $($_.turn_id): 服务端计时未提供"; return }
    $i = 0
    foreach ($r in $reqs) {
        $i++
        [pscustomobject]@{
            Turn = $_.turn_id
            Request = $i
            ServerTotal_ms = if ($null -ne $r.server_total_ms) { $r.server_total_ms } else { '未提供' }
            ModelLoad_ms = if ($null -ne $r.model_load_ms) { $r.model_load_ms } else { '未提供' }
            Input_ms = if ($null -ne $r.input_processing_ms) { $r.input_processing_ms } else { '未提供' }
            Gen_ms = if ($null -ne $r.generation_ms) { $r.generation_ms } else { '未提供' }
            OutTokens = if ($null -ne $r.output_tokens) { $r.output_tokens } else { '未提供' }
        }
    }
} | Format-Table -AutoSize
```

注意：服务端字段**只有已有服务真的返回时才有**；`$_.latencies_ms` 与 `backend_diagnostics` 是两套口径。不要把缺失值强转 `double` 得 0，也不要把 repair 请求与首次请求平均成一条。预热 A/B 是另一次实验，不要与 HTTP 开关同时改变。新机器仍须已有所配置的模型与服务（本次不安装/不换模型），复测不承诺相同毫秒数。
