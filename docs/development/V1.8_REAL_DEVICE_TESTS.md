# V1.8 Windows 真实设备验收手册

本手册只使用 Windows PowerShell 语法。它不下载模型、不修改 Git 历史，也不要求 STM32。真实播放和麦克风测试优先佩戴耳机；项目没有回声消除，使用扬声器可能让麦克风重新识别机器人的播报。

## 1. 进入仓库并选择 Python

在仓库根目录打开 PowerShell，然后执行：

```powershell
if (Test-Path .\venv\Scripts\python.exe) {
    $Python = ".\venv\Scripts\python.exe"
} elseif (Test-Path .\.venv\Scripts\python.exe) {
    $Python = ".\.venv\Scripts\python.exe"
} else {
    throw "未找到 venv 或 .venv，请先创建虚拟环境并安装项目依赖。"
}

$env:OUTPUT_DIR = "outputs/v1.8-manual"
$env:MEMORY_FILE = "outputs/v1.8-manual/memory.json"
$env:STATE_FILE = "outputs/v1.8-manual/emotion_state.json"
New-Item -ItemType Directory -Force -Path $env:OUTPUT_DIR | Out-Null
```

预期：`$Python` 指向现有解释器，隔离输出位于被 `.gitignore` 排除的 `outputs/v1.8-manual`。不要把该目录中的音频、事件或对话记忆提交到 Git。

## 2. 环境与 CLI 检查

```powershell
& $Python --version
& $Python .\main.py --help
& $Python .\main.py --diagnose
& $Python -m pip check
```

通过标准：Python 可运行；help 中出现 `--streaming`；诊断能列出输入/输出设备或给出明确 warning；`pip check` 输出 `No broken requirements found.`。失败时先处理诊断中的依赖或默认设备问题，不要重复下载已经存在的模型。

## 3. 自动化回归基线

```powershell
& $Python -m compileall -q main.py srtp_voice tests
& $Python -m pytest -q
& $Python -m pip check
git diff --check
```

通过标准：四条命令退出码均为 0，没有失败测试，也没有 whitespace error。该步骤不访问真实模型、麦克风或 Piper。

## 4. Ollama 与模型标签检查

```powershell
ollama list
Get-Content -Encoding UTF8 .\.env | Select-String '^(LLM_BACKEND|LLM_MODEL|LLM_OLLAMA_BASE_URL|LLM_FALLBACK_TO_MOCK)='
```

预期：`LLM_BACKEND=ollama`，`LLM_MODEL` 与 `ollama list` 的完整标签逐字一致。真实验收建议 `LLM_FALLBACK_TO_MOCK=0`，避免 mock 掩盖 Ollama 错误。若服务未启动，在另一个 PowerShell 窗口运行 `ollama serve`；不要在已有服务运行时重复启动。

## 5. 流式文本输出

先用 `--no-play` 隔离播放设备：

```powershell
& $Python .\main.py --mode console --text "请用三句简短中文解释什么是流式语音交互。" --streaming --no-play
```

预期：回答文字在模型整段完成前逐步出现；每个完整句子会进入 TTS；最后打印 `final_reply`，并生成 `reply.wav`、事件和指标。失败标志包括长时间完全无输出、乱码、重复整段、用户问题被原样当作答案、或 traceback。

## 6. UTF-8 中文复杂问答

```powershell
& $Python .\main.py --mode console --text "请准确保留这些内容：型号ZXQ-407-A9、金额￥128.50、日期2026-08-09；再解释‘流式输出（streaming）’为什么能降低首响延迟？" --streaming --no-play
```

通过标准：终端、`last_action.json` 和事件 JSON 中中文不乱码；型号、金额和日期没有丢字或重复；最终 reply 是实际回答而不是问题复述。

## 7. 首 token 延迟

完成第 5 或第 6 步后执行：

```powershell
$Metrics = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_metrics.json" | ConvertFrom-Json
$Metrics.last_turn.latencies_ms | Format-List time_to_first_token_ms,llm_first_token_ms,turn_total_ms
```

预期：三个值存在且非负。`llm_first_token_ms` 是请求开始到首 token；`time_to_first_token_ms` 是整轮开始到首 token。记录数值但不要设定脱离硬件和模型的固定阈值；同一机器连续测量时明显退化才判失败。

## 8. 首句与首段音频延迟

```powershell
$Metrics = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_metrics.json" | ConvertFrom-Json
$Metrics.last_turn.latencies_ms | Format-List first_sentence_ms,tts_first_chunk_ms,time_to_first_audio_ms,time_to_playback_ms
```

预期：`first_sentence_ms`、`tts_first_chunk_ms` 和 `time_to_first_audio_ms` 存在且非负；未使用 `--no-play` 时还应有 `time_to_playback_ms`。首段音频应在最终完整回答前开始准备。

## 9. 麦克风 partial/final ASR

确认 `.env` 使用真实 faster-whisper 和目标 Piper 后，佩戴耳机执行：

```powershell
& $Python .\main.py --mode vad --streaming --no-play
```

校准阶段保持安静，然后说一条包含结尾信息的句子，例如“今天测试的最后三个字是七八九”。预期：终端可出现一个或多个 `[ASR partial]`；只出现一个 `final_user_text`；final 保留“七八九”；随后只触发一轮回答。没有 partial 但 final 正确不一定失败，短句或机器速度可能来不及产生中间快照。

## 10. 验证记忆只写 final

```powershell
$Events = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_events.json" | ConvertFrom-Json
$Memory = Get-Content -Raw -Encoding UTF8 "$env:MEMORY_FILE" | ConvertFrom-Json
$Events | Where-Object event_type -eq 'asr_partial' | Select-Object event_type,turn_id,sequence
$Events | Where-Object event_type -eq 'asr_final' | Select-Object event_type,turn_id,sequence
$Memory | Select-Object user_text,reply_text
```

通过标准：事件可有多个 `asr_partial`，每轮只有一个 `asr_final`；memory 每轮只新增一个对象，`user_text` 等于 final 而不是任一 partial。检查时不要把私人语音文本粘贴到公开 issue。

## 11. Piper 分句合成与播放顺序

去掉 `--no-play`，佩戴耳机执行：

```powershell
& $Python .\main.py --mode console --text "请严格用三句短句介绍三种夏季饮品，每句只介绍一种，不要寒暄。" --streaming
$Events = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_events.json" | ConvertFrom-Json
$Events | Where-Object event_type -in @('sentence_ready','audio_chunk_ready','playback_started','playback_finished') |
    Select-Object event_type,sequence,@{Name='chunk';Expression={$_.payload.chunk_sequence}} |
    Format-Table -AutoSize
```

通过标准：`chunk_sequence` 从 0 连续递增；每个 chunk 的 ready/start/finish 不倒序；事件文本没有纯空白或纯标点块；听感顺序与 final reply 一致；没有无关的固定寒暄/自我介绍；`reply.wav` 是所有句子合并后的兼容输出。

## 12. 回答过程中安全打断

执行一个较长回答并在已经开始播报后按一次 `Ctrl+C`：

```powershell
& $Python .\main.py --mode console --text "请分十句详细介绍语音交互系统的组成。" --streaming
```

随后检查：

```powershell
$Events = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_events.json" | ConvertFrom-Json
$Events | Select-Object -Last 10 event_type,turn_id,sequence
Get-Process piper -ErrorAction SilentlyContinue
```

通过标准：程序回到提示符，最后事件包含 `turn_cancelled`，状态机保存为 Idle，没有由本次任务遗留的 Piper 进程或播放线程。当前自动语音 barge-in 默认关闭；这一步验证显式取消和清理，不验证回声环境中的自动抢话。

## 13. 耳机与回声回采

真实麦克风测试必须优先使用耳机，并把系统默认输出设备切到耳机。若只能使用扬声器，应降低音量、拉开麦克风距离，并观察 partial 是否出现机器人刚播报的内容；一旦发生即判为回采环境失败，不应通过降低 ASR 断言来掩盖。

## 14. 连续 10 轮与长时间稳定性

```powershell
$env:MEMORY_FILE = "$env:OUTPUT_DIR/stability-memory.json"
& $Python .\main.py --mode vad --continuous --streaming
```

完成至少 10 轮，每轮等待回到监听后再说下一句。独立的 stability memory 避免前面验收提示词污染长测。记录第 1、5、10 轮的首 token/首音频延迟。通过标准：没有死锁、重复 final、跨轮旧音频、无限内存增长或队列持续满；`turn_id` 每轮不同。若单轮后端失败，应保存带 `failed=true` 和当前 `turn_id` 的 metrics、回到 Idle 并继续下一轮，而不是结束进程；独立的 `streaming_failure_metrics.json` 与 `streaming_failure_events.json` 不应被后续成功轮次或 Ctrl+C 覆盖。长时间测试建议 30 分钟，结束时按一次 `Ctrl+C`，再执行第 12 步的残留进程检查。

## 15. 失败恢复

用临时环境变量指向不可用 endpoint，验证失败后状态回到 Idle；`finally` 会恢复当前 PowerShell 变量：

```powershell
$OldChatUrl = $env:LLM_OLLAMA_CHAT_URL
$OldTimeout = $env:LLM_TIMEOUT_SECONDS
try {
    $env:LLM_OLLAMA_CHAT_URL = "http://127.0.0.1:1/api/chat"
    $env:LLM_TIMEOUT_SECONDS = "2"
    & $Python .\main.py --mode console --text "失败恢复测试" --streaming --no-play
} finally {
    if ($null -eq $OldChatUrl) { Remove-Item Env:LLM_OLLAMA_CHAT_URL -ErrorAction SilentlyContinue } else { $env:LLM_OLLAMA_CHAT_URL = $OldChatUrl }
    if ($null -eq $OldTimeout) { Remove-Item Env:LLM_TIMEOUT_SECONDS -ErrorAction SilentlyContinue } else { $env:LLM_TIMEOUT_SECONDS = $OldTimeout }
}

& $Python .\main.py --mode console --text "恢复后请回答：二加三等于几？" --streaming --no-play
```

预期：第一条给出明确连接错误且 `last_state.json` 为 Idle；恢复后第二条成功，不需要删除缓存或重装模型。

## 16. 输出位置

本手册使用的文件均位于 `$env:OUTPUT_DIR`：

- `user_input.wav`：final VAD 语句或 console 占位音频。
- `reply.wav`：按句音频合并后的兼容 WAV。
- `last_action.json`、`serial_packet.json`：最终动作与兼容串口包。
- `streaming_events.json`：有界事件历史。
- `streaming_metrics.json`：最近一轮时延和滚动 p50/p95。
- `streaming_failure_events.json`：最近一次失败轮次的持久事件快照，仅在失败时生成/更新。
- `streaming_failure_metrics.json`：最近一次失败轮次的持久错误与时延快照。
- `last_state.json`、`emotion_state.json`、`memory.json`：状态与 final-only 记忆。

```powershell
Get-ChildItem $env:OUTPUT_DIR | Select-Object Name,Length,LastWriteTime
```

## 17. 总体通过/失败判定

全部通过需要同时满足：自动化测试通过；token/中文/句子顺序正确；final 唯一且 partial 不进 memory；取消后无旧音频；指标字段存在；10 轮无死锁；真实 Piper 和麦克风符合预期。任一 traceback、乱码、音频跨 turn、重复 final、无限队列增长、线程/子进程残留或同步模式回归都判失败。

## 18. 需要回传的最小日志范围

发生问题时请回传：失败命令；从 `[TURN` 或 `[CONFIG]` 开始到 traceback 结束的终端文本；`streaming_metrics.json`；问题 turn 的最后 30 个事件（可把 `payload.text` 改为 `<redacted>`）；以及 `last_state.json`。不要回传 `.env`、Token、个人音频、完整私人对话或模型文件。

```powershell
$Events = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_events.json" | ConvertFrom-Json
$Events | Select-Object -Last 30 event_type,turn_id,sequence,timestamp
Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_metrics.json"
Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/last_state.json"
Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_failure_metrics.json" -ErrorAction SilentlyContinue
```

## 19. 安全终止

前台运行时按一次 `Ctrl+C`，等待“状态机已回到 Idle”后再关闭 PowerShell。不要用任务管理器连续强杀，也不要删除模型目录。若终端已异常退出，先运行 `Get-Process piper -ErrorAction SilentlyContinue` 和 `& $Python .\main.py --diagnose`，确认资源恢复后再继续。

## 20. 测试完成后的恢复

隔离输出可以保留用于诊断；它已被 Git 忽略。要恢复当前 PowerShell 的默认输出配置，只移除本手册设置的三个环境变量：

```powershell
Remove-Item Env:OUTPUT_DIR -ErrorAction SilentlyContinue
Remove-Item Env:MEMORY_FILE -ErrorAction SilentlyContinue
Remove-Item Env:STATE_FILE -ErrorAction SilentlyContinue
```

不需要修改或删除 `.env`，也不需要清理模型缓存。
