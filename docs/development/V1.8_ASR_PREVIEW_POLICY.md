# V1.8：最终识别优先，预览可回退

目标是减少仅用于终端显示的临时转写工作，不削短老人/儿童的句中停顿，不把不完整的partial当成问题提交。默认`STREAM_ASR_PARTIALS_ENABLED=1`保留原增量预览；`0`关闭预览提交，但仍流式采集、使用原VAD参数、保存完整音频并独立执行一次完整final ASR。同步/file/文本输入路径不变。

## 行为和取舍

- 开启：能看到不断更新的临时转写；若停嘴时旧预览仍在执行，必须安全等待它结束，不能并发抢同一ASR实例或丢弃完整final。
- 关闭：没有`[ASR partial]`，也不复制预览PCM/提交预览解码任务；最终识别仍存在，模型加载、最终推理和LLM/TTS延迟并未消失。
- 默认仍开启，未修改用户`.env`或全局环境。严格bool接受`1/true/yes/on`与`0/false/no/off`；拼写错误报安全键名，不回显原输入。
- 快照记录实际bool并区分fingerprint，不能删除该差异来伪造同配置。静音阈值仍可使用已有`SILENCE_MS`，延长会增加真正说完后的等待，缩短可能截断思考停顿；本轮不改默认。

## 同一台机器的PowerShell复测

在项目根目录的同一个测试终端运行。确认原Ollama服务及已有所需模型正常；在线doctor有warning/error时先看原因，服务未启动不等于模型丢失，不为此重装或自动换模型。耳机、相同公开问题、自然完整发声；每组6–10轮，第一轮单列，不用第一轮直接代表冷启动。不要上传录音/事件原文/记忆。

```powershell
.\venv\Scripts\python.exe -m tools.workbench doctor --online
if ($LASTEXITCODE -ne 0) { throw '先处理自检警告/错误，尚未开始复测' }

# 先测0；下次将同一行改为1，运行整个片段，输出目录始终新建。
$env:STREAM_ASR_PARTIALS_ENABLED = '0'
$runName = 'asr-preview-' + $env:STREAM_ASR_PARTIALS_ENABLED + '-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '-' + ([Guid]::NewGuid().ToString('N').Substring(0,8))
$env:OUTPUT_DIR = "outputs/$runName"
$env:MEMORY_FILE = "$env:OUTPUT_DIR/memory.json"
$env:STATE_FILE = "$env:OUTPUT_DIR/emotion_state.json"
.\venv\Scripts\python.exe -m tools.workbench snapshot --output "$env:OUTPUT_DIR/recording-context.json" --label $runName
if ($LASTEXITCODE -ne 0) { throw '快照失败，尚未开始复测' }
.\venv\Scripts\python.exe main.py --mode vad --streaming --continuous
# 每组问答结束按Ctrl+C，再执行：
.\venv\Scripts\python.exe -m tools.workbench baseline --metrics "$env:OUTPUT_DIR/streaming_metrics.json" --recording-metadata "$env:OUTPUT_DIR/recording-context.json" --output "$env:OUTPUT_DIR/timing-baseline.json" --measurement real --label $runName
$m = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_metrics.json" | ConvertFrom-Json
$m.summary | ConvertTo-Json -Depth 6
$round = 0
$m.turns | ForEach-Object {
    $round++
    [pscustomobject]@{
        Round = $round
        ASR_Final_ms = $_.latencies_ms.asr_final_ms
        LLM_ms = $_.latencies_ms.llm_first_token_ms
        TTS_ms = $_.latencies_ms.tts_first_chunk_ms
        Endpoint_Playback_ms = $_.latencies_ms.endpoint_to_playback_ms
    }
} | Format-Table -AutoSize
```

为减少次序影响，两次测试可采用`0→1`和`1→0`；输出/记忆每组独立，其余参数保持不变，核对问题是否被完整听清。两组故意不同配置，现有严格`baseline --compare`会报不可比，这是来源保护，不应改快照绕过；比较时明确只有预览开关变化、逐轮/样本限制和识别质量。关闭预览后缺少`asr_first_partial_ms`是预期，不造零。

## 本轮证据与限制

DeepSeek实现主要接线和自有门禁；Codex独立审查实际差异/原始失败，修正挂起夹具并补完整PCM、final、默认/旧Namespace、取消、错误与隐私门禁。定向57项、默认完整1021项通过（76.33秒），编译/依赖检查通过；这些不是产品速度测量。

Codex因首版实验接线/无限等待问题接管重放器，经合成接口验证后单次有界执行：本机已有Piper生成3条公开问题，缓存faster-whisper-small/CPU int8/4线程/beam1/中文，20ms帧、0.8秒预览间隔，每题各模式两次AB/BA，共12轮。真实模型推理与原collector/session/final运行，但硬件帧来源被有限实时重放替代，不测声卡队列/麦克风/LLM/播放或老人儿童听感。

原始JSON、真实退出0的日志、有限runner、被否决首版及失败记录保存在`outputs/workbench/accessibility-20261005/`。单机3题×2对的小样本，未给统计显著性或真实人群结论；CI/Review以当前提交现场记录为准。预览影响CPU和端点在途等待时，该模式可能有用；无在途干扰时不能承诺可察觉提升。

韵律加速候选暖态约省28ms、首次加载库约116ms，并有边界/异常/状态问题，未接受且源码已恢复；失败日志与提案保存在`outputs/workbench/accessibility-20261005/`。默认预览不开关不代表已自动提速；真实收益应从本轮公开重放和上述设备复测判断，不仅凭“少调用”宣称降低多少毫秒。
