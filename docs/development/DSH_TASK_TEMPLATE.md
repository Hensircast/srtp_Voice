# dsh 派工与交接模板

按需加载，先读取仓库根目录 AGENTS.md 与 WORK_CHECKPOINT.md。派工前确认本项目的工作区/会话、正在执行的任务和外发权限；不自动新建会话、不启动重复任务。

## 有限任务

- 目标：本批次要解决的问题；本次无需解决的事项。
- 输入：必要文件、基线、已有结论和证据路径；只读取相关内容。
- 范围：明确允许读取/修改的项目相对目录、文件及外部来源。
- 约束：方法、依赖、设备、时长/算力/磁盘峰值/费用上限，用户授权与禁止事项；预算未知时不得开展依赖该预算的动作。
- 产物：明确文件名、格式、日志与检查点位置；不得覆盖用户结果。
- 验收：可复现命令、有效断言、来源校验或基线对比；标注模拟/真实环境。
- 停止点：具体的危险操作必须在执行前报告对象、影响和恢复办法；权限不足、预算将超限、证据冲突或未增加证据的重复失败须报告，不自行扩大范围。

返回短报：已完成事项 → 关键结果 → 证据路径 → 异常/待裁定问题 → 建议下一步。

## 断点更新

在任务启动、阶段结果、异常、暂停和交付时更新 WORK_CHECKPOINT.md，必要时保留详细日志到任务文件。记录计划/已启动/已完成/已验证的区别。

- 当前目标、验收标准和已核实授权；未核实项。
- 已完成、未完成及失败事项；关键证据路径及版本。
- dsh 工作区/会话标识、当前任务、状态、进程和输出位置；不可获取的状态明确标注。
- 软件/数据/模型版本，复现入口及需要加载的最小文件集合。
- 资源占用、额度读数的时间/范围、预算、阻塞、恢复步骤及下一步。
- 安全保存完成情况；恢复需要的模型、数据、配置和进程状态分别列出。

不得写入密钥、私人对话或个人录音。工作区连接详情只记必要的非敏感标识；授权不明时不发送项目材料给外部服务。
