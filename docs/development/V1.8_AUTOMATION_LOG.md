### 2026-08-10 真实设备反馈修复

- 核心修复提交：`0328ff4`（句块过滤、静音 lip-sync、TTS fail-fast、失败诊断与连续恢复）。
- PowerShell JSON：用户报告的 `ConvertFrom-Json` 失败可由 Windows PowerShell 默认编码稳定复现；原文件经 Python UTF-8 解码为合法 JSON。验收手册所有 JSON 读取命令已显式增加 `-Encoding UTF8`。
- TTS 根因：软标点立即切分与最大等待可能把 Markdown 尾随空白刷成独立块；Piper 因空输入失败，纯静音 WAV 又使 lip-sync 峰值归一化出现 `0/0`。运行时现会合并未达到最少字符数的软标点碎片、跳过纯空白/纯标点、保持连续 chunk 序号，并为静音峰值设置安全下限。
- 连续模式：单轮异常现在保存当前 turn 的 error/events/metrics、恢复 Idle 并继续监听；独立 failure 快照不会被后续成功轮次或 Ctrl+C 覆盖；失败轮次不写入 memory。TTS 首次失败会取消同 turn 的后续块，但工作线程继续服务下一 turn。
- 回复质量：流式 system prompt 禁止无关寒暄/自我介绍、禁止照搬历史固定开场/结尾，并要求不输出 Markdown 换行；长测使用独立 memory，避免验收提示词污染。
- 定向回归：57 项通过，覆盖空白尾块、短软标点、静音 WAV、TTS fail-fast、失败诊断、UTF-8 PowerShell 手册和提示词边界。
- 真实复验：本机 `ollama/qwen3:4b-instruct` + Piper 的家常菜推荐成功退出；130 个事件连续，8 个句子块和 8 个音频块的 chunk 序号均为 0..7，全部包含可发音内容，无空块、除零或残留 Piper 进程。

## 已知风险与待实测项

- 单调时间只用于耗时计算，不可解释为真实日期时间。
- faster-whisper partial 使用增长 PCM 快照而不是原生增量解码器状态。
- 流式文本与 action 分离；流式 action 使用确定性默认值，同步结构化策略路径继续保留。
- 最大等待切分在新 token、显式轮询或流结束时检查；底层 HTTP 无字节期间受 LLM timeout 约束。
- 真实 Ollama 与 Piper 的 `--no-play` 路径已复验；麦克风、实际音频播放、主观首响延迟和回声回采仍需按验收手册实测。
- 无回声消除时应优先使用耳机，避免扬声器声音被麦克风重新识别。
