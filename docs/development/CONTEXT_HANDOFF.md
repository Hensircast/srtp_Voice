# SRTP 精简上下文入口

适用于当前任务继续、上下文恢复或用户自行打开的新任务。无需复制整个聊天历史；可直接使用以下启动说明：

> 在本 SRTP 仓库继续工作。先完整读取根目录 AGENTS.md，再读 docs/development/WORK_CHECKPOINT.md，并核实其中的分支、文件、PR 和助手任务状态。按断点推进已授权的下一步，已有结果不重复执行。历史依据按需从 WORK_HISTORY.md 索引定向查阅。
>
> 采用 DeepSeek/dsh 主执行、Codex 规划审查和复杂攻关模式。先核实本项目既有 dsh 会话、正在运行的任务及材料权限，再派具体、有限、可验收的任务；入口缺失时报告并完成必要独立检查。详细派工格式按需读取 DSH_TASK_TEMPLATE.md。
>
> 当前先按断点完成轻量工作台及真实 dsh 协作。语音首响长尾仍是后续待办，前两轮慢的原因尚未确认；不将工具建设说成已提速。保留真实模型/硬件验证与离线 CI 的区别。最新状态只以核实后的 WORK_CHECKPOINT.md 为准，不按旧阶段日志的“当前状态”重做任务或扩大权限。

## 文件职责

- AGENTS.md：稳定规则，通常每次恢复必读。
- WORK_CHECKPOINT.md：唯一的当前待办/授权/现场状态入口，阶段完成或异常时更新。
- WORK_HISTORY.md：已完成工作的证据索引，按需要查章节。
- DSH_TASK_TEMPLATE.md：派工/交接格式，实际派工时才加载。
- 各 V1.8 专题文档：详细设计、审计、测试命令，按索引读取。

这些文档保存工作依据；模型、配置、数据、录音和进程仍需分别核实。此入口不调用或重置应用会话，也不表示后台任务已结束。
