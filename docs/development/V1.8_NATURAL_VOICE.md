| 路径/模块 | 审查深度与裁定 |
| --- | --- |
| main、streaming_runtime、streaming_tts | 深审主链、按轮事件、工厂资源所有权、取消、文件生命周期；合成与播放分成两个有界阶段 |

这是按风险和实际主链开展的全项目审查，不等于所有文件每行均完成形式化验证。未做原生 Ubuntu 音频设备、真人试听或模型质量评分。

自然模式由 `STREAM_NATURAL_BOUNDARIES=1` 控制，直接 `SentenceChunker` API 默认仍保留旧模式；`0` 可恢复旧切分策略。
`TTS_PIPER_PERSISTENT=1` 只影响流式路径；`0` 可恢复每句单次 CLI。
常驻模式使用已有 CLI 的 `--json-input`：每行输入 text/output_file，stdout 返回纯输出路径。
回执不代表文件已关闭，读取前仍检查完整 WAV。异常句不自动重试，失败记录保留，后续轮可重建干净会话。

没有把 `tts_style` 的 speed/pitch/volume 当作已生效的语音情感控制：当前这些字段仍是动作策略元数据，未接入实际合成。
Piper 声线自身的平淡音色不能仅靠分句和预取消除；本轮改善目标是减少碎句、等合成的空档和模板化措辞。
Piper 已有句末静音，不额外加固定 sleep。首句硬句界原本已可预览，也不将已有功能重复计为新优化。

## 追加：可选 Piper 预热（默认关闭）

`STREAM_TTS_WARMUP=1` 只在流式 runtime 创建后、首次 Listening 前，对自有常驻 Piper 合成固定公开短句，不播放、不写记忆、不发 turn 事件、不覆盖正式音频。同步、mock、edge 和常驻 opt-out 不创建预热进程/文件。成功可重复调用而不重复合成；失败保留异常供启动入口简短报告，继续监听并允许后续重试。

合成回执/WAV 等待使用不超过 5 秒的独立 timeout（尊重更小的配置值），不是操作系统进程启动/回收的绝对总耗时保证。正常回答沿用原超时；拒绝非有限/非正覆盖值。预热、开始轮次与关闭共享生命周期锁，活动轮和已关闭 runtime 不接受预热；异常不会因 TypeError 被静默重试。新开关只接受明确布尔值，非法值报错。

完整回归退出后，串行 off → on → on → off，保持已有模型/公开六句：

| 组 | 关闭预热：首句合成 | 开启预热：准备 / 首句合成 | 准备加首句合成 |
| --- | --- | --- | --- |
| 1 | 560.000 ms | 476.709 / 247.738 ms | 724.447 ms |
| 2（反向次序） | 580.781 ms | 470.573 / 238.604 ms | 709.177 ms |

首句 TTS 的等待在此小样本下降约 56–59%，但程序准备加首句合成反而增加约 128–164 ms。因此这是把等待移到监听前，不是整体冷启动加速；保持默认关闭。没有控制系统缓存/其他后台负载，不作统计显著性、真人自然度或端到端速度承诺。早期另四次诊断可能与 full 回归重叠，完整保留但不作为上述配对结果。

## 追加：流式 ASR 内存直传

`STREAM_ASR_IN_MEMORY=1` 默认启用，仅 faster-whisper、严格整数 16000 Hz、mono little-endian PCM16 快照走数组路径；其他采样率/后端、没有 hook 的自定义 adapter 或开关为0，保留原临时 WAV 路径及清理。同步文件入口不变，正式 user_input.wav 仍保存。空串识别是有效结果，不会再解码；hook 返回非法类型或失败直接报错，不静默回退重试。

float32 数值转换与已安装库的解码规则一致：不裁音、不重采样，不改语言/beam/VAD/上下文参数，共用同一模型实例、参数构造和 generator 错误处理。已核对 [faster-whisper v1.2.1 官方数组入口](https://github.com/SYSTRAN/faster-whisper/blob/v1.2.1/faster_whisper/transcribe.py) 与本机安装源码。

Codex 使用实际安装的 PyAV/faster-whisper 解码器，将全部 **65,536 个 int16 取值**与内存路径逐样本核对，结果完全相同。对4.096秒固定测试信号按 WAV→内存→内存→WAV 循环5次（每种10次）测量，两个独立记录的纯中转/解码中位数为 **109.1635→0.0865 ms**、**79.957→0.059 ms**。这里模型使用明确的 decode-only 桩，数字不包含语音识别推理，不能算完整 ASR 或开口速度改善。

进一步使用已有离线缓存的真实 faster-whisper 模型，对此前 Piper 固定公开句生成的音频，以同一16k PCM、同一参数、同一模型实例，WAV→内存→内存→WAV测量：

| 观察对 | 文件路径识别 | 内存路径识别 |
| --- | --- | --- |
| 1 | 1982.396 ms | 1634.752 ms |
| 2（反向次序） | 1706.436 ms | 1615.348 ms |
