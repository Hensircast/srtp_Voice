## 审查与改动范围

| 路径/模块 | 审查深度与裁定 |
| --- | --- |
| main、streaming_runtime、streaming_tts | 深审主链、按轮事件、工厂资源所有权、取消、文件生命周期；合成与播放分成两个有界阶段 |
| tts、piper_session、config | 深审 CLI 协议、超时与退出回收；流式 Piper 常驻复用，原同步 adapter 保留单次 CLI |
| streaming、llm | 深审分句、NDJSON、UTF-8、回声保护、措辞与计时；保护小数/词边界，首句直接回答，多句播放记录最后完成 |
| asr、streaming_asr、audio_io、vad | 核对模型复用、partial/final、端点调度、校准和录音路径；保留已有实现，不盲目缩短静音窗口 |
| ser、prosody、emotion_fusion、emotion_state | 核对 warmup、保守融合、F0/静音数值边界、原子保存；本轮不改变研究指标或识别算法 |
| memory、state_machine、lip_sync、serial_out、types、utils | 核对调用接口、final-only 记忆、唇动归属、JSON 编码和兼容边界；不扩大到 STM32/V1.7 |
| tools 工作台与 dsh、诊断、CI、测试/文档 | 接口与风险定向审查，已有历史 Review 和回归作为补充；快照新增本轮语音调优选项 |

这是按风险和实际主链开展的全项目审查，不等于所有文件每行均完成形式化验证。未做原生 Ubuntu 音频设备、真人试听或模型质量评分。

自然模式由 `STREAM_NATURAL_BOUNDARIES=1` 控制，直接 `SentenceChunker` API 默认仍保留旧模式；`0` 可恢复旧切分策略。
`TTS_PIPER_PERSISTENT=1` 只影响流式路径；`0` 可恢复每句单次 CLI。
常驻模式使用已有 CLI 的 `--json-input`：每行输入 text/output_file，stdout 返回纯输出路径。
回执不代表文件已关闭，读取前仍检查完整 WAV。异常句不自动重试，失败记录保留，后续轮可重建干净会话。

没有把 `tts_style` 的 speed/pitch/volume 当作已生效的语音情感控制：当前这些字段仍是动作策略元数据，未接入实际合成。
Piper 声线自身的平淡音色不能仅靠分句和预取消除；本轮改善目标是减少碎句、等合成的空档和模板化措辞。
Piper 已有句末静音，不额外加固定 sleep。首句硬句界原本已可预览，也不将已有功能重复计为新优化。

## 已完成的真实 Piper 测量

同一 Windows/Python 3.12.10、同一个已有 63,201,294 字节模型、固定六句公开做菜文本。
按 one-shot → persistent → persistent → one-shot 顺序运行，分别保存所有结果；不播放，不使用用户对话。

| 组 | 单次 CLI 首次 / 后续中位数 | 常驻模式首次 / 后续中位数 | 后续中位耗时变化 |
| --- | --- | --- | --- |
| 1 | 591.570 / 499.080 ms | 692.593 / 228.149 ms | -54.29% |
| 2（反向次序） | 584.379 / 518.718 ms | 644.989 / 232.634 ms | -55.15% |

每种模式每组后续样本仅 5 句。首次常驻合成在这两组中更慢约 61–101 ms，不能宣称冷启动提速。
更早首个基线观测 3048.954 ms 原样保存在本地，但没有受控冷缓存条件，不拿它计算改善比例。
合成包含模型固有随机性，音频时长略有不同；这是小样本工程诊断，不是统计显著性或真人自然度研究。
纯 TTS 结果不能替代 endpoint_to_playback、实际声卡出声或完整 ASR/LLM 链路。

本地原始证据：`outputs/workbench/voice-ux-20260930/bench-paired-{oneshot,persistent}-{1,2}/timings.json` 与公开文本 WAV；不提交音频或本机环境。
源码内复现入口：

```powershell
$benchId = [Guid]::NewGuid().ToString('N')
.\venv\Scripts\python.exe -m tools.benchmark_piper --mode one-shot --output "outputs/workbench/piper-$benchId-oneshot"
.\venv\Scripts\python.exe -m tools.benchmark_piper --mode persistent --output "outputs/workbench/piper-$benchId-persistent"
```

已有模型/CLI 路径来自本机 `.env`；新机器须先准备相同兼容 CLI 和模型，不会自动从仓库获取权重。
Ubuntu 可使用 `python -m tools.benchmark_piper`，结果目录也必须是新的 outputs 子目录；没有对新机器承诺相同毫秒数。

## 下一轮真实 PowerShell 复测

先开启已经安装的 Ollama 应用或在另一个终端运行 `ollama serve`，确认自己的已有模型能使用。
本轮只读核验时默认 `127.0.0.1:11434` 没有监听；这证明当时服务不可用，不证明模型缺失，不需要据此重装/换模型。
若已有 Ollama 正在其他地址运行，保持你实际配置的地址，不同时启动第二个实例。

在项目根目录的**新终端**运行，所有环境覆盖仅影响该终端；保持本机原 ASR/Piper 模型路径。

```powershell
Set-Location 'D:\code\VScode\Py\srtp_Voice'
$runName = 'voice-natural-' + [Guid]::NewGuid().ToString('N')
$env:OUTPUT_DIR = "outputs/$runName"
$env:MEMORY_FILE = "$env:OUTPUT_DIR/memory.json"
$env:STATE_FILE = "$env:OUTPUT_DIR/emotion_state.json"
$env:TTS_BACKEND = 'piper'
$env:TTS_PIPER_PERSISTENT = '1'
$env:STREAM_NATURAL_BOUNDARIES = '1'
.\venv\Scripts\python.exe -m tools.workbench doctor --online
.\venv\Scripts\python.exe -m tools.workbench snapshot --output "$env:OUTPUT_DIR/recording-context.json" --label $runName
.\venv\Scripts\python.exe main.py --mode vad --streaming --continuous
# 完成 6–10 轮后 Ctrl+C；仍在同一终端保存同轮证据。
.\venv\Scripts\python.exe -m tools.workbench baseline --metrics "$env:OUTPUT_DIR/streaming_metrics.json" --recording-metadata "$env:OUTPUT_DIR/recording-context.json" --output "$env:OUTPUT_DIR/timing-baseline.json" --measurement real --label $runName
$m = Get-Content -Raw -Encoding UTF8 "$env:OUTPUT_DIR/streaming_metrics.json" | ConvertFrom-Json
$m.summary | ConvertTo-Json -Depth 6
$m.turns | ForEach-Object { [pscustomobject]@{
    ASR_ms = $_.latencies_ms.asr_final_ms
    LLM_ms = $_.latencies_ms.llm_first_token_ms
    TTS_ms = $_.latencies_ms.tts_first_chunk_ms
    EndToPlay_ms = $_.latencies_ms.endpoint_to_playback_ms
} } | Format-Table -AutoSize
```

建议依次问：三道夏季家常菜、一道菜两步做法、解释 3.14 与版本 1.23、短句中英文混读、明确要求长答案、明确要求原样重复，再重复两道同题。
记录是否有碎句/不当停顿、漏读重读、无关自我介绍、取消后旧轮继续说话。不要把自己等待开口的时间包含在“说完到回应”的主观计时里。
不要对外提供录音、memory 或事件文字；优先分享脱敏计时基线。第一条观测不自动称为冷启动。
